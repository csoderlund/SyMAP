This page describes using Blast or Diamond for computing the hits for SyMAP.

Pros: (1) Loading a blast file is much faster than SyMAP running MUMmer. (2) Any numbers of blast file hits can be 'added' to the existing hits.

Cons: (1) It does not work if one of the genomic sequence is not annotated and it does not perform gene discovery. (2) It loses the exon/intron alignment coordinates, hence, the alignment to the 2D exon/intron structure is incorrect. (3) The user must obtain and manually run Blast or Diamond.

The steps are very easy:

  • Use the SyMAP Export to create a FASTA file of the protein, CDS or Exons.
  • Run Blast or Diamond on them and put the results in data/seq_results/<project1>_to_<project2>/blast.
  • Set Load Blast files from Parameters, then run Selected Pairs or Selected Redo (add to existing hits).
Please read the following for the details.

Create the FASTA files

When you load the project, you may request that either the Exons or CDSs be loaded; see Parameters.
  1. Select View for the project, then Export.

    →If you have loaded the CDSs, then you can create a file of Proteins and/or Spliced CDSs.


    →If you have loaded the Exons , you can create a file of Spliced Exons.

  2. Likewise, export the proteins or spliced transcripts from the second project.

The export can take awhile, e.g. for the demoArab 13,476 genes:

  • It took 13 minutes on my old MacOS x86_64
  • It took 3 minutes on my newer MacOS M4
  • It uses a single CPU and does not use much memory.

By default, the exported files will be in the SyMAP /export directory.
The FASTA header line uses the ID= value from the GFF file attribute; see Annotation file.

Run Blast or Diamond

SyMAP does not run Blast or Diamond for you. You must download Blast or Diamond.
For protein sequences, use Blastp or Diamond.
For nucleotide sequences, use Blastn.

The output file must be the tabular format (-outfmt 6).

It is recommended that the results only show the top 5 hits per gene (-max_target_seqs 5).

For the Demo, you can copy and paste the commands from Example below.

Load Blast files

Start SyMAP and select Pair Parameters.
Select the Load Blast files option.

If protein files are being compared, select Proteins, else select Nucleotides. For protein files, the length of the hits is multiplied by 3 to better approximate its alignment.

When you select Save, the directory data/<project1>_to_<project2>/blast will be created.

Exit SyMAP and move the blast tab file(s) to data/<project1>_to_<project2>/blast.
Restart SyMAP and select Selected Pair; a popup (as shown on right) will confirm your parameters; select Confirm.

SyMAP will load the blast hits, then execute the Collinear algorithm and Synteny algorithm.

SyMAP will load ALL files in the /blast directory.
  • The hits coordinates are set to start at the beginning of the first CDS or exon. That is, the hit does not align correctly with the gene (MUMmer hits do align correctly).

  • Only one hit per gene pair from a file will be loaded unless there are hits that do not overlap.
    The blast hits are not clustered like the MUMmer hits are.

  • If a hit between a gene pair already exists in the database, only the Hit Type column will be updated to indicate that the hit was found in multiple files (see Query table).

Add to existing hits

  • In order to load both MUMmer and Blast hits, first run SyMAP with MUMmer. Then add the Blast hits.

  • The Load&Synteny can be executed with any number of blast files.
    If multiple files are being loaded, make sure they are all from protein sequences or all from nucleotide sequences, and have the parameter correctly set to Protein or Nucleotide, respectively.
    SyMAP does NOT check if a file is already loaded.

  • MUMmer, Blast and Diamond produce different subsets of gene pair hits. Moreover, Blast and Diamond produce different subsets depending one whether project1 is the blast database or project2. By loading all variations, the maximum number of gene pair hits will be in the SyMAP database.

Remove hits added by a given file: There is no way to do this. Clear Pair then reload the desired files.

Example and Details

By default, the exported files are written to /export. I generally create a directory
   data/seq_results/<project1>_to_<project2>/export
and move the FASTA files here, and run Blast/Diamond from this directory.
Then I copy the desired *.tsv files to ../blast.
Note: Clear Pair only removes the /align and /blast directories.

The following filenames are suggested naming; SyMAP does not care as long as they are outfmt 6.

Diamond: 

diamond makedb --in demoBrapProt.faa -d brapdb
diamond blastp -q demoArabProt.faa -d brapdb  -o diamBrapProt.tsv -f 6 -k 5 -p 4

Blastp: 

makeblastdb -in demoBrapProt.faa -dbtype prot -out brapAAdb
blastp -query demoArabProt.faa -db brapAAdb -out bltBrapProt.tsv -outfmt 6 -max_target_seqs 5 -num_threads 4

Blastn 

makeblastdb -in demoBrapExon.fna -dbtype nucl -out brapNTdb
blastn -query demoArabExon.fna -db brapNTdb -out bltBrapExon.tsv -outfmt 6 -max_target_seqs 5 -num_threads 4
or 
makeblastdb -in demoBrapCDS.fna -dbtype nucl -out brapNTdb
blastn -query demoArabCDS.fna -db brapNTdb -out bltBrapCDS.tsv -outfmt 6 -max_target_seqs 5 -num_threads 4

Query table

  • EE indicates a MUMmer hit. The Bp12 means it was also found in both blast files.
  • A Bp1 indicates it was only found in the 1st blast file,
    A Bp2 indicates it was only found in the 2nd blast file.
  • Load Blast will add numbers for up to 9 blast files.
All hit values are from the FIRST hit entered into the database, e.g. the %Olap and %Id from the first row are from the EE hit.
